# 活动信息提取规则（崩坏：星穹铁道）

自动化维护活动信息时，从公告/动态中提取字段的规则依据。**只覆盖星铁**；
原神的规则见 [../genshin/RULES.md](../genshin/RULES.md)。

星铁与原神的公告格式、版本节奏都不同，**不要拿原神的规则套**。差异见 §二。
下面每条规则都由 `selftest.py` 用真实公告夹具（`fixtures/`）断言。

## 一、数据来源

| 来源 | 位置 | 给出什么 |
|---|---|---|
| **版本更新说明** | 米游社 `4.5版本「挥掷千星的筹码」版本更新说明` | 版本名、本版起止、**下版本日期**、高难 4 类期名+日期、部分活动日期 |
| **更新预告** | 米游社 `4.5版本预下载&更新预告` | 版本更新日 + 版本号 + 版本名（T−2，最准） |
| **卡池公告** | 米游社 `4.5版本活动跃迁（其一/其二）` | 卡池起止 + 5 星角色全名 |
| **活动说明** | 米游社 `「X」活动：…` / `「X」活动说明` | 起止 + 描述 + 配图 |
| **无名勋礼** | 米游社 `4.5版本「无名勋礼」更新` | 大月卡起止 |
| **B站前瞻** | uid `1340190821` | 前瞻直播日期时间、版本上线日期 |

**版本更新说明是总纲**，每版本开服当天发布，一份就给出：

- `4.5版本的持续时间为 2026/08/26 4.5版本更新后 - 2026/09/28 06:00`
  → 本版本一开服就知道**下个版本的准确日期**（4.6 = 9/28），提前 33 天，不用推理
- `■玩法` 段 → 高难四支的期名与日期：
  ```
  ●本期主题：「异相仲裁•军团再临」
  ●末日幻影•仙客天狼 2026/08/31 04:00 - 2026/10/05 03:59
  ●虚构叙事•立界开篇 2026/09/14 04:00 - 2026/10/19 03:59
  ●混沌回忆•扫除风暴 2026/08/17 04:00 - 2026/09/28 06:00
  ```

因为这一份，星铁**全部类型都可自动化**，且不需要原神那样的周期性推理。

## 二、与原神的关键格式差异

| 项 | 原神 | 星铁 |
|---|---|---|
| 段落标记 | `〓活动时间〓` | `▌活动时间` / `▌限时活动期` / `▌开启时间`（三种都用）；版更公告里还会标成 `■活动时间` |
| 卡池标题 | 标题自带卡池名+5星（`「孤灯夜访」祈愿：「诡灯陌影·菲林斯(雷)」概率UP`） | 标题只有 `（其一/其二）`，**5 星名在正文里** |
| 卡池公告关键词 | `祈愿` + `概率` | `X.Y版本活动跃迁` |
| 大月卡 | 纪行（`XX纪行`，每版本名不同） | 无名勋礼（**名字永远一样**，需带版本号区分） |
| 维护预告 | `X.Y版本更新维护预告`，正文 `〓更新维护信息〓` | `X.Y版本预下载&更新预告`，正文 `列车组预计于 A 进行版本更新维护…更新至X.Y版本「NAME」` |
| 嵌套书名号 | — | `「镇伏『贪饕』，汇聚愿力」`、`「反贪『砖』家」`。原神的 `[「『]([^」』]{2,40})[」』]` 会截断成 `「镇伏『贪饕`，星铁必须用 `「([^「」]{2,60})」` |
| 版本周期 | 固定 42 天 | **不固定**（4.4→4.5 = 42 天，4.5→4.6 = 33 天），不能 `锚点+42×n` 外推 |

## 三、时间与日边界

**结束时刻在清晨（≤ 06:00）→ 结束日减一天；白天时段（11:59 / 15:00）→ 照抄。**

```python
us = re.findall(r'(\d{4})/(\d{1,2})/(\d{1,2})(?:\s+(\d{1,2}):(\d{2}))?', seg)
start = us[0]        # 首个日期，照抄
end   = us[-1]       # 末个日期；若带了时刻且 hh*60+mm <= 360 → end -= 1 天
```

06:00 是停机维护时刻、04:00/03:59 是游戏日分界，两者玩家都玩不到那一整天，所以都减；
11:59 / 15:00 是白天时段，照抄。

> ⚠️ **无名勋礼（大月卡）在版本结束前就先结束**，所以它的结束日**不等于**版本期间终点，
> 一律**以大月卡自己的公告为准**，不要拿版本周期去套、也不要拿版本期间去"纠正"它。
> 实测：4.4 版本期间 7/15~8/25，但 4.4「无名勋礼」是 7/15~**8/23**。
> 大月卡走的是 `find_battle_passes` → 抓它自己的公告正文，本来就取的是公告值。

实测核对（全部与版本更新说明 / 现有数据一致）：

| 文本 | 推出 | 数据文件 |
|---|---|---|
| `2026/07/27 04:00 - 2026/08/10 03:59`（位面分裂） | 7/27 ~ **8/09** | 已订正为 8/09 |
| `2026/08/14 04:00 - 2026/08/24 03:59`（花藏繁生） | 8/14 ~ 8/23 | 8/14~8/23 ✓ |
| `2026/09/19 04:00 - 2026/09/28 03:59`（异器盈界） | 9/19 ~ 9/27 | 9/19~9/27 ✓ |
| `2026/08/26 4.5版本更新后 - 2026/09/28 03:59`（超限/无名勋礼） | 8/26 ~ 9/27 | 8/26~9/27 ✓ |
| `2026/09/12 12:00 - 2026/09/28 03:59`（方寸大冒险） | 9/12 ~ 9/27 | 9/12~9/27 ✓ |
| `2026/07/15 4.4版本更新后 - 2026/08/25 15:00`（4.4卡池） | 7/15 ~ 8/25 | 7/15~8/25 ✓ |
| `2026/08/17 04:00 - 2026/09/28 06:00`（混沌回忆） | 8/17 ~ 9/27 | 8/17~9/27 ✓ |
| `2026/08/03 04:00 - 2026/09/14 03:59`（虚构叙事） | 8/03 ~ 9/13 | 8/03~9/13 ✓ |

> ——它是下一版的起点。

## 四、卡池标题规则

星铁卡池公告标题只有「（其一/其二）」，5 星名全在正文里，标题必须现拼：

- 正文有 `本期活动跃迁时间为 A - B，包含如下内容` → **全公告一个时间段**，
  5★ = 所有 `角色活动跃迁期间，限定5星角色「X」`（顺序去重）。其一/其二都是这种。
- 没有该句（4.4 其二那种含「铭心之萃」返场池的）→ 开头段落**逐句分组**，
  每句一组 5★ + 自己的 `跃迁时间为 …`。
- 标题 = 该组 5★ 用 `「」` 连接 + `跃迁`。

拼出的标题与数据文件里既有的条目**逐字一致**（selftest 断言），所以卡池不需要任何
日期或标题推理——原神的 `inference.infer_banner_dates` 在星铁完全用不上。

| 公告 | 5★ | 拼出 |
|---|---|---|
| 4.5 其二 | 砂金•戏浪 + 不死途 | `「砂金•戏浪（欢愉•量子）」「不死途（巡猎•雷）」跃迁` |
| 4.5 其一 | 知更鸟•晴歌 + 风堇 | `「知更鸟•晴歌（记忆•风）」「风堇（记忆•风）」跃迁` |
| 4.4 其二 句1 | 姬子•启行 | `「姬子•启行（智识•火）」跃迁` 7/15~8/25 |
| 4.4 其二 句2 | 刻律德菈 + 那刻夏 + 砂金 | `「刻律德菈（同谐•风）」「那刻夏（智识•风）」「砂金（存护•虚数）」跃迁` 8/05~8/25 |

同一期卡池会在「其一」「其二」里各出现一次（姬子•启行整版都在池，两篇都写了它），
所以落盘前按标题去重。

## 五、标题规则

| 类型 | 标题取值 |
|---|---|
| 常规活动 / 版本大活动 | `「活动名」`（取最外层「」，兼容嵌套） |
| 卡池 | 见 §四 |
| 版本更新 | `《崩坏：星穹铁道》X.Y 版本「版本名」停服更新` |
| 版本更新（版本名未知） | `《崩坏：星穹铁道》X.Y 版本停服更新` + `待确认版本` 标签 |
| 前瞻直播 | `《崩坏：星穹铁道》X.Y 版本「版本名」前瞻特别节目` |
| 无名勋礼（大月卡） | `X.Y版本「无名勋礼」`（期名不随版本变，必须带版本号，否则去重键会撞） |
| 高难挑战 | `型名·期名`（如 `异相仲裁·军团再临`），型名 ∈ 异相仲裁/末日幻影/虚构叙事/混沌回忆 |

## 六、公告分类（按标题判断，不看正文）

命中 `EXCLUDE`（`rules.py`）即不当作「常规/版本大活动」。除版本更新说明、更新预告、
卡池、无名勋礼这些由各自解析函数单独处理的以外，还有一类是**本就不该进日历**的：

- 账号封禁、商店上新、意见反馈、优化说明、已知问题、跃迁记录、小程序、云•星穹铁道
- 角色前瞻、光锥前瞻、更新电台、专题展示页、互动抽奖、联名、创作者激励
- **任务说明**（开拓任务的公告，「开拓任务」这个词未必在标题里）
- **赛季扩充**（常驻玩法的版本内更新）
- **权益升级**（《云•星穹铁道》的促销，崩铁侧也会发一条同名公告）

> 后三条是实测补的：它们的标题带「」，会被当成活动，但正文里根本没有活动时间段，
> 于是每轮都白抓一次正文、又永远落不了盘（无日期被闸掉）。

## 七、身份、去重与校准

与原神**共用同一套机制**（`common/keys.py` + `common/calibrate.py`），主键规则一致：
常规活动/版本大活动/卡池/大月卡按完整标题，版本更新与前瞻直播按 (类型, 版本号)。

> ⚠️ **双倍掉落类（`「位面分裂」`/`「花藏繁生」`/`「异器盈界」`）是例外：主键带开始日期**
> （`DATED_KEYED_PREFIXES`）。这三类每期标题**一字不变**，只认标题的话第二期会被当成
> 重复条目静默丢掉——实测 2026-09-21 发现 9 月那期「位面分裂」（9/07~9/20）根本没进日历，
> 因为 7 月那期（7/27~8/09）已占了同一个标题。
>
> 为什么不索性让**所有**常规活动都按 (标题, 日期) 定身份：那样一旦有人在编辑器里手工订正
> 了某条的日期，它的主键就变了，下一轮会被当成新活动重复插一遍——而「只新增、绝不改已有」
> 是整套自动化的底线。所以只对**已知会重复**的名字开这个口子。

星铁侧的具体校准来源：

| 类型 | 校准依据 | 标记值 |
|---|---|---|
| 高难挑战 | 米游社**版本更新说明**（唯一的权威来源） | `米游社版本更新说明` |
| 版本更新 | 米游社维护预告（T−2）> B站前瞻公告 | `米游社维护预告` / `B站前瞻公告` |
| 前瞻直播 | B站前瞻公告 | `B站前瞻公告` |

> `高难挑战` 是本次为星铁加进 `CALIBRATED_TYPES` 的：星铁的高难期名与日期都写在版本
> 更新说明里（权威），而它恰恰是最容易错的一类。对原神是空转——原神的高难
> （深境螺旋/幻想真境剧诗）无公告，sources 里没有该类型的键。

## 八、B站解析的两个坑

- **前瞻闸门用「正式播出」而不是「开启」**：星铁的**回顾长图**动态里也有「开启」
  （「开启新的冒险旅途」），用「开启」会把回顾当预告，且日期会取错（回顾里只有兑换码失效日）。实测踩到过。
- **动态条数 `DYN_LIMIT = 80`、米游社 `PAGE_SIZE = 40`**：比原神的 30 宽，因为版本更新说明
  必须留在窗口内（实测 4.4 的说明排在第 44 条，page_size=30 会漏掉）。
